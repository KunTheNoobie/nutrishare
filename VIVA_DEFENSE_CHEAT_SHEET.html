🎯 Design Pattern: Observer Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say:
"The Observer Pattern is a GoF behavioural design pattern that defines a one-to-many dependency between objects. When the subject undergoes a state change, all its registered observers are automatically notified and updated without the subject having tight coupling to their concrete implementations."

Why in Module 1: Publishing food triggers audit logging, sending emails to nearby NGOs, and pushing alerts. Putting this in DonationController violates the Single Responsibility Principle. The Observer decouples model events from side-effects.

❓ Tough Tutor Questions

Q: Why not just put email dispatch inside the controller?
Answer: "Placing email dispatch in the controller means database seeders, API endpoints, or console commands would fail to trigger notifications. The Observer hooks into Eloquent lifecycle events directly, ensuring consistent side-effects across all entry points while keeping the controller lightweight."
Q: What if the notification mail server times out? Does it roll back the donation?
Answer: "No. The Observer dispatches SendDonationNotificationJob to Laravel's asynchronous queue. Database persistence is committed independently. The queue worker handles retries independently without blocking the user or rolling back the database transaction."

🎯 Design Pattern: State Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say:
"The State Pattern is a GoF behavioural design pattern that allows an object to alter its behaviour when its internal state changes. The object will appear to change its class by delegating state-specific execution to concrete state objects."

Why in Module 3 (Tutor Trap Alert): An Enum is NOT a State Pattern! As lifecycle rules change (e.g., verifying vehicle assignment before collection), an Enum violates OCP. The State Pattern isolates each state's transitions, notifications, and rules into dedicated classes.

❓ Tough Tutor Questions

Q: Can't you just use an Enum with helper methods instead of State classes?
Answer: "No, tutor. An Enum represents static data, whereas the State Pattern encapsulates dynamic behaviour. As business rules expand—such as temperature verification in ApprovedState or digital signature capture in CollectedState—an Enum violates the Open/Closed Principle by forcing changes to existing switch blocks."
Q: What stops two NGOs from claiming the same donation simultaneously?
Answer: "In ClaimController::store(), we check that donation status is available and verify no active claims exist for that NGO. When approved, donation status transitions to claimed, excluding it from active queries."

🎯 Design Pattern: Strategy Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say:
"The Strategy Pattern is a GoF behavioural design pattern that defines a family of algorithms, encapsulates each one into a separate class, and makes them interchangeable. It lets the algorithm vary independently from clients that use it."

Why in Module 4: Routine notices use Email, but critical cold-chain failures (e.g., freezer temperature breaches) require SMS. The Strategy pattern lets the application switch delivery channels at runtime without coupling code to concrete messaging APIs. 

// app/Strategies/Notification/NotificationDispatcher.php (Line 48)
public function resolveStrategy(string $channel): NotificationStrategyInterface {
    return match (strtolower($channel)) {
        'sms'   => new SmsStrategy(),
        'email' => new EmailStrategy(),
        default => new EmailStrategy(),
    };
}

❓ Tough Tutor Questions

Q: What is the difference between Strategy Pattern and Liew's Observer Pattern?
Answer: "The Observer Pattern is a one-to-many publish-subscribe mechanism where a subject broadcasts state changes to multiple unknown listeners. The Strategy Pattern is a one-to-one algorithmic interchange where a context executes one interchangeable algorithm (e.g., Email vs. SMS) at a time."
Q: What prevents an attacker from reusing an expired HMAC signed URL next week?
Answer: "When generated with URL::temporarySignedRoute(), an expires UNIX timestamp is included in the payload before computing the HMAC hash. The middleware verifies that now()->timestamp <= expires. If expired, access is rejected immediately."
