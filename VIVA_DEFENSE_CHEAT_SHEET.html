🎯 Design Pattern: Observer Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say (Easy Words):
"The Observer Pattern is a design pattern where one main object automatically notifies many listening objects whenever its state changes, without needing to know who they are."

Why we use it here: When food is published, we need to send emails, write logs, and notify NGOs. If we put all that code inside DonationController, the controller becomes messy and hard to maintain. With Observer, Laravel listens to the Donation model and sends notifications in the background. 

// 1. Register Observer: app/Providers/EventServiceProvider.php (Line 27)
\App\Models\Donation::observe(\App\Observers\DonationObserver::class);

// 2. Observer catches event: app/Observers/DonationObserver.php (Lines 41-45)
public function created(Donation $donation): void {
    SendDonationNotificationJob::dispatch($donation); // Runs in background queue
}

🛡️ Software Security Defense (Why basic validation is not enough)

NOT BASIC INPUT VALIDATION

Threat 1: CSRF — Fake Cross-Site Submission (A05)

The Attack: A hacker creates a malicious website with a hidden form pointing to our donate URL. If a logged-in donor visits their page, their browser automatically sends our session cookies and posts fake donations.
Why validation fails: Form validation only checks if title and quantity are strings or numbers. Since the fake submission sends valid text, validation passes 100%! It cannot tell where the request came from.
How we fix it: We put @csrf in the form. Laravel gives the user's browser a secret random token. If a request doesn't have this secret token, Laravel rejects it with Error 419.

NOT BASIC INPUT VALIDATION

Threat 2: Stored XSS — Malicious JavaScript (OWASP A07)

The Attack: A hacker puts <script>stealCookies()</script> into the food description. If we print it directly, any user or admin opening that page will have their session stolen.
Why validation fails: We cannot simply ban < or >, because normal donors write things like <Fresh Bread> or Qty < 10. Validation shouldn't break normal text.
How we fix it: We display it using Blade's {{ $donation->description }}. Laravel automatically turns < into &lt;, so the browser displays it as harmless plain text instead of running it as code.

🎯 Design Pattern: Factory Method Pattern (GoF Creational)

🗣️ Look Tutor in the Eye & Say (Easy Words):
"The Factory Method Pattern is a creational pattern that provides an interface for creating objects, but lets subclasses decide which exact class to instantiate."

Why we use it here: NGOs and Donors have completely different signup rules. NGOs need pending status and document uploads; Donors are approved right away. Instead of writing messy switch-case statements inside AuthController, the factory delegates the creation logic to dedicated creator classes.

        'ngo'   => new NgoCreator(),
        'donor' => new DonorCreator(),
        default => new DonorCreator(),
    };
}

// 2. Controller just calls it: app/Http/Controllers/AuthController.php (Line 36)

🛡️ Software Security Defense (Why basic validation is not enough)

NOT BASIC INPUT VALIDATION

Threat 1: Broken Access Control — Forced Browsing (A01)

The Attack: A normal NGO user types /admin/verifications directly into the browser URL to approve their own organization.
Why validation fails: Submitting the approval form sends action=approved, which is valid text. Validation cannot check if the person submitting is an admin or not!
How we fix it: We use CheckRole middleware. It checks $request->user()->role from the encrypted server session. If you are not an admin, it immediately stops you with Error 403 Forbidden.

NOT BASIC INPUT VALIDATION

Threat 2: OTP Brute-Force — Guessing 6-Digit Codes (A07)

The Attack: A hacker uses an automated bot to test all 1,000,000 combinations (000000 to 999999) to guess the password reset OTP.
Why validation fails: Form validation only checks digits:6. Since every guess is 6 numbers, validation allows all of them!
How we fix it: We use throttle:6,1 (max 6 guesses per minute). The OTP also expires after 10 minutes and is deleted immediately once verified.

        'trust_rating'=> $user ? $user->averageRating() : null,
    ]), 200);
}

🎯 Design Pattern: State Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say (Easy Words):
"The State Pattern allows an object to change its behavior when its internal state changes, appearing as if it changed its class."

Why not just use an Enum? (Tutor Trap): An Enum is just a static label. But each stage in our delivery has different rules (e.g. you cannot collect until a vehicle is assigned). If we used an Enum, we would have ugly if-else checks everywhere. The State Pattern keeps each state's rules inside its own class. 

// 1. Context Model delegates to state: app/Models/Claim.php (Line 93)
public function getStateObject(): ClaimState {
    return match ($this->status) {
        'approved'  => new ApprovedState($this),
        'collected' => new CollectedState($this),
        default     => new PendingState($this),
    };
}

// 2. State controls actions: app/States/Claim/PendingState.php (Line 21)
public function allowedActions(): array {
    return ['approve', 'reject', 'cancel']; // 'collect' is blocked here!
}

🛡️ Software Security Defense (Why basic validation is not enough)

NOT BASIC INPUT VALIDATION

Threat 1: BOLA / IDOR — Snooping Other Claims (A01)

The Attack: An NGO changes the URL from /claims/5 to /claims/6 to see another NGO's logistics details and driver phone number.
Why validation fails: 6 is a valid number in the database, so route validation lets it pass.
How we fix it: We use ClaimPolicy. It checks if the logged-in user actually owns the claim ($claim->user_id === $user->id). If not, it blocks them with Error 403 Forbidden.

NOT BASIC INPUT VALIDATION

Threat 2: State Tampering — Skipping Approval (A04)

The Attack: An attacker sends a fake request with action=collect on a pending claim to take food without donor approval.
Why validation fails: "collect" is a valid word, so basic validation accepts it.
How we fix it: The controller checks PendingState::canPerform('collect'), which returns false. You cannot collect food while it is still pending.

🎯 Design Pattern: Strategy Pattern (GoF Behavioural)

🗣️ Look Tutor in the Eye & Say (Easy Words):
"The Strategy Pattern defines a family of algorithms, puts each one into its own class, and makes them swappable at runtime."

Why we use it here: Normal alerts use Email, but urgent cold-chain temperature emergencies need SMS. The Strategy pattern lets us swap delivery channels cleanly without editing or risking bugs in the controller code. 

// 1. Context switches strategy: app/Strategies/Notification/NotificationDispatcher.php (Line 48)
public function resolveStrategy(string $channel): NotificationStrategyInterface {
    return match (strtolower($channel)) {
        'sms'   => new SmsStrategy(),
        'email' => new EmailStrategy(),
        default => new EmailStrategy(),
    };
}

🛡️ Software Security Defense (Why basic validation is not enough)

NOT BASIC INPUT VALIDATION

Threat 1: Log Injection — Forging Audit Records (A09)

The Attack: A hacker types Enter (\r\n) inside a note: "Chicken\r\n[10:00PM] ADMIN: Hacked". In the log file, it creates a fake second line to trick the admin.
Why validation fails: Note boxes legitimately allow multiline text, so normal validation lets it through.
How we fix it: In SystemLog.php, we have an Eloquent mutator that automatically cleans input with SecurityHelper::sanitizeLogInput(), removing all \r and \n before saving to the database.

NOT BASIC INPUT VALIDATION

Threat 2: URL Tampering on Action Links (A01/A04)

The Attack: A quick-claim link is sent with ?donation=1. An attacker changes it to ?donation=2 to take another donation.
Why validation fails: 2 is a valid number, so validation allows it.
How we fix it: We use HMAC Signed URLs (URL::temporarySignedRoute). Laravel signs the link with our secret APP_KEY. If an attacker changes even one number, the signature breaks and Laravel blocks it.

// app/Http/Controllers/Api/InventoryApiController.php (Lines 80-108)
public function checkSafety(Request $request): JsonResponse {
    $ifa = SecurityHelper::validateIfaRequest($request->all());

        'requestID' => $ifa['requestID'],
        'food_item' => [
            'id'            => $item->id,
            'name'          => $item->name,
            'safety_status' => $isSafe ? 'SAFE' : 'EXPIRED / AT RISK',
        ],
    ]), 200);
}
